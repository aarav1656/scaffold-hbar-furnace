# Add a buyback cooldown

## Goal

A token team wants a floor on how often the engine buys. Add an owner-set
cooldown, in seconds, between two buybacks that spend. It applies to the
scheduled run, the owner's manual `buyback()` and the dry run alike, and the
Policy panel shows it. Follow `AGENTS.md`; the engine's invariants do not change.

## Existing app (preserve)

- `FurnaceEngine` keeps every current function, event, error and the `Config`
  struct. The constructor, `Deploy.s.sol` and `FurnaceBase._config()` do not
  change: the cooldown is off (0) until the owner sets it.
- All current Foundry tests keep passing.
- `packages/nextjs/contracts/deployedContracts.ts` is generated by the deploy
  and is not edited by hand.
- `runScheduled` still books its successor first and never reverts; `buyback`
  still burns only the tokens the swap delivered.

## Feature to implement

1. `packages/foundry/contracts/FurnaceEngine.sol`
   - Append `Cooldown` as the last member of `enum Skip`.
   - `uint256 public constant MAX_BUYBACK_COOLDOWN = 1 days;`
   - `uint256 public buybackCooldown;` (seconds, 0 means none) and
     `uint256 public lastBuybackAt;` (consensus second of the last buyback that spent).
   - `event BuybackCooldownSet(uint256 buybackCooldown);`
   - `function setBuybackCooldown(uint256 value) external onlyOwner`: reverts
     `BadConfig` above `MAX_BUYBACK_COOLDOWN`, otherwise stores and emits.
   - `_plan()` returns `Skip.Cooldown` while
     `block.timestamp < lastBuybackAt + buybackCooldown`. The check sits after
     the `NotReady` check and before the oracle is read, so a run inside its
     cooldown needs no oracle. `buyback()` does not re-check it.
   - `buyback()` stamps `lastBuybackAt = block.timestamp` only on the path that
     spends, after the skip return. A run skipped for any reason does not start
     or extend the cooldown.
2. `packages/foundry/test/FurnaceSetup.t.sol`: the reviewed state-changing
   surface list gains `setBuybackCooldown` (AGENTS.md invariant 1).
3. `packages/foundry/test/FurnaceCooldown.t.sol`, built on `FurnaceBase`, with
   at least three tests: the setter's owner check and bound, a skip inside the
   cooldown and a spend after it, and default behaviour with the cooldown off.
   Do not create `HarnessCooldownAcceptance.t.sol`; the harness copies its own
   suite under that name for the run.
4. `packages/nextjs`
   - `utils/furnace/constants.ts`: `SKIP_REASONS` gains `"Cooldown"` in the same
     position as the Solidity enum, `SKIP_TEXT` gets its sentence, and a
     `COOLDOWN_ABI` (`parseAbi`) carries `buybackCooldown()` and
     `lastBuybackAt()` so the page needs no edit to the generated ABI.
   - `hooks/furnace/useEngine.ts`: read both through `COOLDOWN_ABI` with
     `Promise.allSettled`; an engine deployed before the cooldown leaves them
     undefined and the page still loads.
   - `components/furnace/PolicyPanel.tsx`: a "Buyback cooldown" row showing the
     duration (or "None"), and the time left before the next buyback opens.
5. `AGENTS.md`: name `setBuybackCooldown` and the cooldown in invariant 5's
   cap order, and keep the stated unit-test count true.

## Out of scope

No constructor or `Config` field, no deploy script change, no owner-controls
form, no edit to `deployedContracts.ts`.
