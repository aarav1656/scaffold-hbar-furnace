# Add a buyback pause

## Goal

A token team wants to stop the engine buying for a while, during an incident or
ahead of an announcement, without losing the schedule that keeps it running.
Add an owner-set pause. While it is on, the scheduled run, the owner's manual
`buyback()` and the dry run all skip with a named reason, the automation chain
keeps booking, and the Policy panel shows the state. Follow `AGENTS.md`; the
engine's invariants do not change.

## Existing app (preserve)

- `FurnaceEngine` keeps every current function, event, error and the `Config`
  struct. The constructor, `Deploy.s.sol` and `FurnaceBase._config()` do not
  change: the engine is not paused until the owner pauses it.
- All current Foundry tests keep passing.
- `packages/nextjs/contracts/deployedContracts.ts` is generated by the deploy
  and is not edited by hand.
- `runScheduled` still books its successor first and never reverts; `buyback`
  still burns only the tokens the swap delivered.

## Feature to implement

1. `packages/foundry/contracts/FurnaceEngine.sol`
   - Append `Paused` as the last member of `enum Skip`.
   - `bool public buybacksPaused;` (false means buying is allowed).
   - `event BuybacksPausedSet(bool paused);`
   - `function setBuybacksPaused(bool paused) external onlyOwner`: stores and
     emits. It moves no HBAR and touches no other state.
   - `_plan()` returns `Skip.Paused` while `buybacksPaused` is true. The check
     sits after the `NotReady` check and before the oracle is read, so a paused
     run needs no oracle. `buyback()` does not re-check it, and `runScheduled`
     is unchanged: a paused scheduled run books its successor first, then skips.
2. `packages/foundry/test/FurnaceSetup.t.sol`: the reviewed state-changing
   surface list gains `setBuybacksPaused` (AGENTS.md invariant 1). The list and
   its length assertion both change.
3. `packages/foundry/test/FurnacePause.t.sol`, built on `FurnaceBase`, with at
   least three tests: the setter's owner check and event, a skip while paused
   and a spend after unpausing, and default behaviour with the pause off. Do not
   create `HarnessPauseAcceptance.t.sol`; the harness copies its own suite under
   that name for the run.
4. `packages/nextjs`
   - `utils/furnace/constants.ts`: `SKIP_REASONS` gains `"Paused"` in the same
     position as the Solidity enum, `SKIP_TEXT` gets its sentence, and a
     `PAUSE_ABI` (`parseAbi`) carries `buybacksPaused()` so the page needs no
     edit to the generated ABI.
   - `hooks/furnace/useEngine.ts`: read it through `PAUSE_ABI` with
     `Promise.allSettled`; an engine deployed before the pause leaves it
     undefined and the page still loads.
   - `components/furnace/PolicyPanel.tsx`: a "Buyback pause" row showing
     "Paused" or "Running".
5. `AGENTS.md`: name `setBuybacksPaused` and the pause in invariant 5's cap
   order, and keep the stated unit-test count true.

## Out of scope

No constructor or `Config` field, no deploy script change, no owner-controls
form, no edit to `deployedContracts.ts`.
